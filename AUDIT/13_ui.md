# 13 — Module review: `ui/control.py` + `ui/overlay.py`

Read in full: ui/control.py L1–326, ui/overlay.py L1–219. Cross-read:
medical_stt/app.py L487–560 (SessionController), config.py save path (module 11).

## What it holds

control.py: borderless Start/Stop window on its own Tk thread; host URL +
masked secret entry saved straight to DPAPI; session-end watcher thread.
overlay.py: cursor-following transcript window, Tk thread + `after(0)`
scheduling (the same fixed lifecycle bug is documented in both files'
docstrings), visual-order text via `to_display`.

## Findings

**F1 · Low · Stop and quit run a blocking join on the Tk mainloop.** FACT:
control.py:281–285 (`_stop`) and L102–104 (`close`, also bound to
WM_DELETE_WINDOW and Escape at L147–148) call
`self._controller.stop()` synchronously; app.py:547–560 joins the session
thread with `timeout=8.0`. The session's own shutdown can take up to ~2 s
(sender drain) + up to 4 s (provider join) + flush, so pressing Stop can
freeze the borderless always-on-top window (no repaint, no drag) for
seconds — on the main thread of a GUI. Impact is UX, not safety: the stop
itself is thorough (module 03). Fix (suggestion only): run `stop()` on a
worker thread and reflect completion via `_ui(...)` like every other state
change in this file.

**F2 · Info · `_watch` polls `is_running` every 0.2 s** (L288–300): one
daemon thread per started session, exits when the session ends. Bounded,
but a poll-interval sleep loop rather than an event; consistent with the
thread-based design.

**F3 · Info · Secret handling in the window is correct.** FACT: entry
masked with `show="•"` (L223–228); `StringVar` cleared immediately after a
successful save (L321) so the plaintext doesn't linger on screen; errors
surfaced via `str(exc)` are SecretStoreError messages that contain no
secret (verified in module 06). Residual exposure is the unavoidable
in-memory `StringVar` while typing.

## Correct in this module (verified)

- Thread discipline: both windows create Tk on a dedicated thread and every
  mutation from other threads goes through `_ui()` → `root.after(0, fn)`
  (control.py:190–203, overlay.py:128–141) — this resolves the module 03
  concern: transcript-callback calls into `set_partial`/`set_done` never
  touch Tk from the SDK thread.
- Overlay lifecycle: `close()` schedules destroy *before* setting `_closed`
  with `force=True` (overlay.py:193–219) — the previously-shipped
  mainloop-hang bug is fixed and regression-documented in the module
  docstring.
- Overlay shows visual-order text only (`to_display`) and never feeds it
  back into processing (overlay.py:155, 167; bidi.py docstring's
  "display is never system of record" is honored); alignment heuristic
  `_is_rtl` (overlay.py:31–46) is display-only.
- No transcript text is logged in either file; status strings are states,
  errors are exception messages already vetted upstream.
- Cursor-follow loop self-cancels on close and is TclError-safe
  (overlay.py:113–131).

## Summary (3 lines)

Both windows follow one clean pattern — Tk on its own thread, everything
else scheduled in — and the old destroy-order hang is fixed with a
documented regression note. One real defect: Stop/quit joins the session
thread on the Tk mainloop, freezing the UI for up to several seconds.
Secret display/clear handling in the settings panel is correct.

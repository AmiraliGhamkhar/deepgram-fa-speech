# 02 — Module review: `host/core.py` (settings, identity, limiters, grant)

Read in full: host/core.py L1–878 (878 lines). Cross-read: host/app.py (module 01),
host/provision.py (module 14), uvicorn proxy_headers source (module 01 F2).

`HostSettings.from_env` L147–243; `ClientRegistry` L554–618 (SHA-256 hashes only);

## Findings

**F1 · Low · `ClientRegistry.from_file` raises `FileNotFoundError`, not
`ConfigurationError`, for a missing registry.** FACT: host/core.py:573
`Path(path).read_text(...)` with no existence handling; host/app.py:394–397
catches only `ConfigurationError` at import. A typo'd `HOST_CLIENTS_FILE`
produces a raw traceback instead of the service's clean fail-fast message.

**F2 · Low · Legacy mode silently collapses all devices into one rate-limit
identity.** FACT: host/core.py:246–248 — with `HOST_CLIENTS_FILE` unset the
registry is `{LEGACY_CLIENT_ID: hash(shared_secret)}`; host/app.py:178–181 then
rate-limits every device against the single `client:legacy` bucket
(120 burst / 60 per 60 s by default). A 50-client deployment that skips
provisioning gets hard-429s at client #~121 requests/min and the per-device
revocation property disappears. The code documents this (L239–245) but nothing
fails or warns at startup — a `log.warning` when `len(registry) <= 1` is the
suggested fix.

**F3 · Low · `authorize()` is production dead code.** FACT: host/core.py:305;
grep shows the only callers are tests (tests/test_host_service.py:72–94). The
route uses `authenticate_client()` (L627). Keeping a second auth function in
the security-critical module invites drift.

**F4 · Info · SHA-256 (unsalted, no KDF) for client secrets.** FACT:
host/core.py:514–518; rationale documented at L521–524 ("256-bit random value
generated by `host/provision.py`... no dictionary to attack"). Safe *only* for
provisioned secrets; the registry file format accepts any hex an operator
paste, and a low-entropy secret chosen by hand is offline-crackable from a
leaked registry file. `host/provision.py` (module 14) is the guard.

**F5 · Info · TTL bounds unverified against current Deepgram API.** FACT:
`DEFAULT_TTL_SECONDS = 30`, `MAX_TTL_SECONDS = 3600` (L39–40), clamped in
`normalize_ttl` L283–291. Whether Deepgram still caps `ttl_seconds` at 3600
for `/v1/auth/grant` is checked in module 18 against current docs.

**F6 · Info · No cross-field validation of burst vs sustained rate.** FACT:
host/app.py:178–188 divides `client_rate_limit_requests / window` for refill
but `capacity` is taken independently from `client_burst`. Setting
`HOST_CLIENT_BURST=10` with rate 60/min silently yields a 10-request ceiling —
no warning. Same for the global pair.

**F7 · Info · `rate_limit_requests` retained-but-warned field.** FACT:
host/core.py:197–208 warns that `HOST_RATE_LIMIT_REQUESTS` is ignored, then
L208 still parses it into `rate_limit_requests` — parsed-but-inert state that
exists to keep the dataclass complete. Covered by a doc-drift test
(tests/test_host_docs.py), acceptable, but the field itself could be deleted.

## Correct in this module (verified)

Secrets: only hashes in memory/registry (L554–572); unknown client id gets a
dummy constant-time compare so timing doesn't reveal id existence (L607–615,
`_UNKNOWN_CLIENT_DIGEST` L620); malformed registry lines refuse startup
(L580–592); grant URL is a module constant (L37) — no SSRF surface; every
network failure path in both sync and async grant maps to a `GrantError` with
an application status and never embeds the key or upstream body (L469–486,
L810–841); token bucket never charges rejected requests (L727–741) and caps
tracked keys at 10,000 with purge + LRU eviction (L743–761); fixed-window
limiter is bounded and self-expiring (L396–432).

## Summary (3 lines)

The identity/limiter core is solid: hashes at rest, constant-time compares,
bounded memory, no credential ever logged. Gaps are operational: missing
registry file surfaces as a raw traceback, legacy single-secret mode silently
shares one rate-limit bucket across all devices, and `authorize()` is dead
production code. TTL constants still need a docs cross-check (module 18).
